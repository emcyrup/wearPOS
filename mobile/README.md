# wearPOS モバイルアプリ（iOS / Android）

Expo（React Native）で作る wearPOS のアプリです。1 つのコードから iOS と Android の両方を作ります。

## いまの段階

**段階 1: 外枠** — アプリの中に今の Web 画面をそのまま表示します。ブラウザと動きが違う部分だけをアプリ側で補っています。

| ブラウザでの動き | アプリ内での扱い |
| --- | --- |
| 別ウィンドウで開く（レジ・レシート） | アプリ内の画面として重ねて開く。左上の「閉じる」か、画面内の「閉じる」で戻る |
| 印刷（レシート・値札） | OS の印刷画面（AirPrint / Android の印刷サービス）を開く |
| 外部サイト・LINE・電話のリンク | 端末のブラウザや LINE アプリで開く |
| サーバーにつながらない | 「再読み込み」ボタン付きの案内を出す |
| Android の戻るボタン | Web 画面の履歴を 1 つ戻る |

ログイン状態とレジ端末の認可（Cookie）は端末に残るので、アプリを閉じても入り直しは不要です。
サーバー側（Web アプリ）は変更していません。

## 今後の予定

| 段階 | 内容 |
| --- | --- |
| 1. 外枠 | ← いまここ |
| 2. 機器連携 | Bluetooth レシートプリンターへの直接印刷、専用スキャナー対応（機種が決まってから） |
| 3. ストア公開 | App Store / Google Play へ提出 |
| 4. ネイティブ化 | レジ画面から順に、Web 表示をネイティブの画面へ置き換える |

段階 4 では `src/app/` に画面のファイルを足していきます（例: `src/app/register.tsx`）。
置き換えていない画面は Web 表示のまま残せるので、1 画面ずつ進められます。

## 手元で動かす

開発者アカウントは不要です。スマートフォンに **Expo Go**（App Store / Google Play で無料）を入れてください。

```bash
cd mobile
npm install
npx expo start
```

ターミナルに出る QR コードを、iPhone は標準のカメラ、Android は Expo Go で読み取ると起動します。
PC とスマートフォンは同じ Wi-Fi につないでください。

### 接続先を変える

既定では本番（`app.json` の `extra.appUrl`）につながります。別のサーバーで試すときは環境変数で上書きします。

```bash
EXPO_PUBLIC_APP_URL=https://staging.example.com npx expo start
```

iOS は `http://` のサーバーへの接続を制限するため、`https://` のサーバーを指定してください。

このアプリは、型チェック・自動テスト・iOS / Android 向けのバンドルまでは確認済みですが、
**実機での動作は未確認**です。最初に次の項目を見てください。

- [ ] 起動するとログイン画面（ログイン済みならトップ）が出る

- [ ] サイドメニューの「レジ ↗」で、レジが上に重なって開く
- [ ] レジの「📷 読み取る」でカメラが起動し、バーコードを読み取れる（初回は許可を求められる）
- [ ] 会計後の「レシートを印刷」でレシートが開き、「印刷」で OS の印刷画面が出る
- [ ] 印刷プレビューのレイアウトが崩れていない（文字化け・スタイルなしになっていない）
- [ ] レシートの「閉じる」、左上の「閉じる」で前の画面に戻る
- [ ] 機内モードにして開くと「サーバーにつながりません」と出て、解除後に「再読み込み」で戻る

うまくいかない項目があれば、どの項目で何が起きたかを教えてください。

## ストア向けのビルド（EAS）

ビルドは Expo のクラウド（EAS Build）で行うので、Mac が無くても iOS アプリを作れます。

必要なもの:

- Expo のアカウント（無料枠あり）
- Apple Developer Program（年 99 ドル）— iOS
- Google Play デベロッパー登録（初回 25 ドル）— Android

```bash
cd mobile
npx eas-cli@latest login
npx eas-cli@latest init                              # 初回だけ。プロジェクトを Expo に登録する
npx eas-cli@latest build --platform all --profile preview      # 社内配布用 (実機に直接入れて試す)
npx eas-cli@latest build --platform all --profile production   # ストア提出用
npx eas-cli@latest submit --platform all                       # ストアへ提出
```

> Web を表示するだけのアプリは、Apple の審査で「アプリである必要がない」と判断されることがあります。
> 段階 2 の機器連携を入れてから提出するのが安全です。

## フォルダ構成

```
mobile/
├── app.json                 アプリ名・識別子・接続先・権限
├── eas.json                 EAS Build の設定
└── src/
    ├── app/                 画面 (Expo Router)。ファイル = 画面
    │   ├── _layout.tsx      画面の並び
    │   ├── index.tsx        起動時の画面 (Web のトップを表示)
    │   └── window.tsx       別ウィンドウとして開く画面 (レジ・レシート)
    ├── components/
    │   └── WebShell.tsx     Web 画面を表示する共通の外枠
    └── lib/
        ├── bridge.ts        Web 画面とネイティブ側をつなぐ橋 (印刷・別ウィンドウ・閉じる)
        ├── navigation.ts    アプリ内で開いてよい URL かの判定
        ├── print-html.ts    印刷用に HTML を整える
        ├── print.ts         OS の印刷機能の呼び出し
        └── config.ts        接続先の解決
```

## 安全面の考え方

- アプリ内の WebView で開くのは**自分のサーバーの画面だけ**です。外部サイトは必ず端末のブラウザへ渡します。
  WebView には印刷などの橋を差し込んでいるため、外部サイトをアプリ内で開くと、そのサイトから橋を呼べてしまいます。
- 橋からの依頼は、送ってきたページが自分のサーバーのものかを確かめてから処理します。
- `wearpos://window?url=...` のようなリンクで外部の URL を渡されても、アプリ内では開きません。
- 秘密情報（API キーなど）はアプリに入れていません。認証は Web と同じ Cookie で行います。
